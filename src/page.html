Was der Viewer versteht – und was nicht
  • Struktur: package, part/item/port/attribute/interface/enum def, Typisierung :, Spezialisierung :>, Redefinition :>>, Multiplizitäten
  • Verbindungen: connect … to …, interface : T connect …, flow of T from … to …, bind, konjugierte Ports ~
  • Verhalten: state, entry; then …, accept … then …, transition first … accept … if … do … then …, action, first/then, decide/merge/fork/join, if … then, done
  • Anforderungen: requirement def <'ID'>, doc, subject, require constraint, satisfy … by …
  • Nicht geprüft: Ausdrücke, Standardbibliothek, Sichtbarkeit, Import-Auflösung. Namen werden über den einfachen Namen aufgelöst; bei Kollisionen wählst du die gültige Definition. Ein sauberes Diagramm heißt nicht, dass das Modell gültig ist.
Navigator: Anforderung → Umsetzung → Schnittstellen → Test. Diagramme: grafische Sichten.
